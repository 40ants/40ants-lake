# Часть 2. Перенос на код

## Комментарий в коде

**Было:**


Нарушения: 8.2.3.11 (составное сказуемое «является методом», два причастных

пользователя»), 8.2.3.13 («сортируются»), 8.2.5.1 (одно предложение, 22 слова).

**Стало:**

```python
# Возвращает активные заказы пользователя.
# Заказы сортирует по дате создания, от новых к старым.
```

## Описание merge request: отчёт, а не задача

**Было:**

```
Переписать кэш профиля и исправить гонку при повторной отправке.
Добавить потребитель очереди orders.paid.
```

Нарушение: инфинитив в описании читается как список невыполненных задач, хотя
работа уже сделана. Пункт 8.2.3.9 требует инфинитив для заголовка, но не для
отчёта.

**Стало:**

```
Что сделано:
- кэш профиля переписан;
- гонка при повторной отправке исправлена;
- добавлен потребитель очереди orders.paid.
```

Краткое причастие сообщает результат. Пункт 8.2.3.13 запрещает страдательный
залог только в инструкциях, а это описательная часть по 8.2.6. Исполнитель
известен из метаданных запроса на слияние, называть его в тексте не нужно.

Развёрнутая форма остаётся нарушением:

| Плохо | Хорошо |
|---|---|
| `Гонка была исправлена.` | `Гонка исправлена.` |
| `Гонка исправляется.` | `Гонка исправлена.` |
| `Я исправил гонку.` | `Гонка исправлена.` |

Проверка: `python3 scripts/utr_lint.py --mode report MR.md`

## Что не правят

**Было и осталось:**

```python
# ВНИМАНИЕ! Если сервис работает в промышленной среде и обрабатывает
# платежи, не отключайте проверку идемпотентности: повторная обработка
# события списывает средства дважды.
```

Предложение длиннее 20 слов. Правило 8.2.7 разрешает превышение: предупреждение
содержит условие и сохраняет полноту. Сокращение потеряло бы условие «в
промышленной среде» и последствие «списывает средства дважды». Пункт 8.2.3.15
запрещает такое сокращение.
