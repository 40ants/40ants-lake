# Адаптация УТР к коду и рабочим артефактам

ГОСТ Р 58049—2017 написан для эксплуатационной документации. Перенос его правил на
код требует решений. Здесь собраны эти решения. Каждое отступление от буквы
стандарта отмечено и обосновано.

## Общий принцип переноса

Стандарт ограничивает **естественный язык**. Код — формальный язык. Граница
проходит по этой линии.

| Объект | Действие |
|---|---|
| Текст комментария, docstring, сообщения | Правила УТР применяют полностью |
| Идентификатор, ключевое слово, путь, команда, ключ конфигурации | Не переводят, не склоняют, не сокращают |
| Название продукта, библиотеки, протокола | Оставляют в оригинальном написании |
| Вывод программы и текст ошибки внешней системы при цитировании | Не переводят. Цитата — одно слово при подсчёте (8.2.5.1) |

Пункт 8.2.3.6 запрещает иностранные слова **при наличии равнозначных русских**. У
идентификатора `retry_count` равнозначного русского термина нет: замена сломает
связь текста с кодом. Поэтому идентификатор остаётся.

## Форма глагола по типу артефакта

Стандарт задаёт две основные формы: неопределённо-личную для описания (8.2.3.3) и
повелительное наклонение множественного числа для инструкций (8.2.3.9, 8.2.5.3).
Ниже — раскладка по артефактам.

### Комментарий и docstring о поведении кода

**Форма: 3-е лицо единственного числа, настоящее время.**

```python
def get_active_orders(user_id: int) -> list[Order]:
    """Возвращает активные заказы пользователя.

    Заказ считают активным при статусе NEW или IN_PROGRESS.
    Порядок сортировки — по дате создания, от новых к старым.
    """
```

**Отступление от 8.2.3.3.** Стандарт предпочитает неопределённо-личную
конструкцию («возвращают»). Для одной функции она читается неверно: подлежащее
подразумевается множественным, хотя действует один объект. Форма «Возвращает»
сохраняет действительный залог и прямой порядок слов. Так навык выполняет цель
пунктов 8.2.3.3 и 8.2.3.4. Неопределённо-личная форма остаётся для описания процессов и
правил.

Что запрещено:

| Плохо | Причина | Хорошо |
|---|---|---|
| `# Заказы возвращаются в порядке создания` | Страдательный залог (8.2.3.13) | `# Возвращает заказы в порядке создания` |
| `# Получение списка заказов пользователя` | Номинативная конструкция, цепочка существительных (8.2.3.10) | `# Возвращает заказы пользователя` |
| `# Возвращаем список` | 1-е лицо множественного числа не предусмотрено (8.2.3.3) | `# Возвращает список` |
| `# Данная функция является методом получения данных` | Составное сказуемое, канцелярит (8.2.3.11) | `# Возвращает данные профиля` |

### Комментарий о причине решения

**Форма: неопределённо-личная или безличная конструкция (8.2.3.3).**

```go
// Индекс по created_at не применяют: планировщик выбирает seq scan
// при выборке более 30 % строк таблицы.
```

```sql
-- Блокировку берут на уровне строки. Табличная блокировка держит очередь
-- обновлений баланса дольше 200 мс.
```

Комментарий о причине отвечает на вопрос «почему», а не «что». Правило 8.2.5.4
(конкретность) требует назвать причину, а не констатировать факт.

### Комментарий-предупреждение

**Форма: условие, затем команда (8.2.7).**

```python
# ВНИМАНИЕ! Метод меняет объект на месте. Перед вызовом скопируйте объект.
```

```java
// ВНИМАНИЕ! Кэш не инвалидируют по событию. При изменении тарифа
// вызовите TariffCache.clear() явно.
```

Порядок обязателен: сначала условие («при изменении тарифа»), потом действие.
Предупреждение сохраняет полноту, даже если превышает 20 слов.

### Инструкция в README и runbook

**Форма: повелительное наклонение множественного числа, глагол первым (8.2.3.9).**

```markdown
## Запуск

1. Установите зависимости: `uv sync`.
2. Скопируйте `.env.example` в `.env`.
3. Укажите строку подключения в переменной `DATABASE_URL`.
4. Запустите миграции: `alembic upgrade head`.
5. Запустите сервис: `uv run app`.
```

Одна команда — один шаг (8.2.5.2). Два действия объединяют, только если их
выполняют одновременно.

### Сообщение об ошибке

**Форма: условие, затем команда. Структура из трёх частей.**

1. Что произошло. Констатация факта, без обвинения.
2. Причина или контекст. Конкретные значения (8.2.5.4).
3. Что сделать. Повелительное наклонение множественного числа.

```
Файл конфигурации не найден: /etc/app/config.yaml.
Создайте файл из образца config.example.yaml.
```

```
Превышен лимит попыток: 5 из 5.
Соединение с брокером не установлено. Проверьте доступность host=mq.internal, port=5672.
```

| Плохо | Причина | Хорошо |
|---|---|---|
| `Что-то пошло не так` | Метафора, нет конкретики (8.2.3.5, 8.2.5.4) | `Сервис платежей вернул код 502. Повторите запрос через минуту.` |
| `Ошибка валидации данных пользователя формы` | Цепочка из четырёх существительных (8.2.3.10) | `Поле email заполнено неверно. Укажите адрес в формате name@example.com.` |
| `Невозможно осуществить подключение` | Канцелярит, номинативность (8.2.3.10) | `Подключиться не удалось. Проверьте сеть.` |

### Запись в лог

**Форма: неопределённо-личная или безличная конструкция.**

```
Соединение закрывают по таймауту: 30 с.
Повторную отправку не выполняют: очередь заполнена.
```

Лог читает и человек, и парсер. Поэтому:

- Одно событие — одна запись.
- Переменную выносят в отдельное поле лога, а не в середину фразы.
- Термин события совпадает с термином в коде и в документации (8.2.3.7).

### Заголовок коммита и merge request

**Форма: неопределённая форма глагола (инфинитив).**

```
Добавить кэш ответов профиля
```

**Отступление от 8.2.3.9.** Стандарт требует повелительное наклонение
множественного числа. Заголовок адресован не исполнителю, а истории изменений:
«Добавьте кэш» звучит как указание. Инфинитив сохраняет действительный залог,
ставит глагол первым и не нарушает запрет единственного числа. Форму прошедшего
времени первого лица («Добавил») не применяют: она вводит скрытого деятеля.

Заголовок отвечает на вопрос «что делает это изменение», поэтому инфинитив тут
уместен: коммит применяют — и он добавляет кэш.

### Описание merge request и тело коммита

**Форма: свершившийся факт — краткое страдательное причастие или прошедшее
время.**

```
Добавить кэш ответов профиля

Профиль запрашивают на каждой странице. Кэш на 60 с снижает нагрузку
на profile-service примерно вдвое.

Что сделано:
- добавлен потребитель очереди `orders.paid`;
- интерфейс `MessageHandler` выделен из класса `OrderService`;
- гонка при повторной отправке исправлена.

Ограничение: кэш не инвалидируют по событию изменения профиля.
Задачу инвалидации ведут в PROJ-1421.
```

**Это не отступление от 8.2.3.13.** Пункт стандарта звучит так: «При написании
инструкций в описании рекомендуется избегать использования страдательного
залога». Он ограничен инструкциями. Описание merge request — не инструкция, а
отчёт о выполненной работе, то есть описательная часть по 8.2.6.

Краткое причастие здесь сообщает результат, а не прячет исполнителя. Исполнитель
известен из метаданных запроса на слияние, поэтому называть его в тексте — лишнее
слово (8.2.3.1). Инфинитив в описании читается неверно: «переписать кэш» — это
задача, которую ещё предстоит сделать, а не отчёт о сделанном.

Границы:

| Форма | Пример | Оценка |
|---|---|---|
| Краткое причастие | `Гонка исправлена.` | Норма для отчёта |
| Прошедшее время, неопределённо-личная | `Гонку исправили.` | Норма, если нужен акцент на действии |
| Развёрнутый страдательный залог | `Гонка была исправлена.` | Лишнее слово. Уберите «была» |
| Возвратная форма | `Гонка исправляется.` | Процесс вместо результата. Не применяют в отчёте |
| Инфинитив | `Исправить гонку.` | Только в заголовке, не в описании |
| Первое лицо | `Я исправил гонку.` | Не применяют (8.2.3.3) |

Линтер знает об этом различии: `--mode report` разрешает краткое причастие, но
продолжает ловить «была исправлена» и «исправляется».

```
Функция обходит список дважды. Объедините проходы в один цикл.

```

## Ограничения переноса отдельных правил

### 8.2.3.18 «кнопка», «ссылка»

Стандарт не рекомендует применять слова типа «кнопка» и «ссылка». В
эксплуатационной документации правило работает: пользователю нужна цель действия.

**Границы применения:**

| Контекст | Решение |
|---|---|
| Пользовательская документация, тексты интерфейса | Правило применяют. Пишут цель: «Узнайте больше», а не «Нажмите на ссылку» |
| Комментарий в коде компонента интерфейса | Правило не применяют. «Кнопка» здесь — термин предметной области |
| Описание компонента в дизайн-системе | Правило не применяют. Термин совпадает с именем компонента |

Основание отступления: пункт 8.2.3.7 требует стандартной терминологии предметной
области. В разработке интерфейсов «кнопка» — стандартный термин.

### 8.2.4.6 Единицы измерения

Правило требует пересчёта в систему страны назначения с оригиналом в скобках.
В коде и логах пересчёт не выполняют: значение приходит из системы. Правило
применяют к документации для пользователя.

Пишите единицу рядом со значением: `30 с`, `512 МиБ`, `200 мс`. Разделяйте
значение и единицу неразрывным пробелом в документации.

### 8.2.5.1 Лимит в 20 слов

Лимит считают по правилам стандарта. Идентификатор, число, аббревиатура и цитата
дают одно слово. Поэтому технический текст редко упирается в лимит по-настоящему.

Дополнительное ограничение для кода: комментарий в одну строку не длиннее длины
строки проекта. Комментарий из более чем трёх предложений выносят в docstring или
в документ.

### 8.2.3.16 Списки

В коде маркированный список внутри комментария допустим. Оформляйте его так:

```python
# Порядок применения правил:
# - точность смысла;
# - единство терминологии;
# - краткость.
```

## Смешение языков

Смешение русского и английского в одном тексте — источник неоднозначности.
Правила:

1. Один комментарий — один язык естественного текста.
2. Идентификаторы и команды не считают сменой языка.
3. Термин, у которого нет принятого русского эквивалента, вводят один раз:
   `очередь недоставленных сообщений (dead letter queue, DLQ)`. Далее применяют
   сокращение (8.2.3.8).
<!-- utr-lint: disable-next-line -->
4. Гибриды не применяют (8.2.3.5): «задеплоить», «зафейлился», «отревьюить».
   Замены — в `lexicon.md`.
5. Кириллические идентификаторы не применяют. Они ломают инструменты и правило
   8.2.3.2 (однозначность): визуально схожие символы `с`, `о`, `а`, `е`, `р`, `х`
   существуют в обоих алфавитах.

## Терминологическая база проекта

Пункт 8.1.3 требует терминологическую базу до внедрения УТР. Для репозитория это
файл глоссария.

Минимальный состав:

- канонический термин для каждого понятия предметной области;
- синонимы, которые заменяют на канонический термин (8.2.3.7);
- сокращение и его полная форма (8.2.3.8);
- соответствие русского термина идентификатору в коде.

Образец: `glossary.example.json`. Передавайте файл линтеру через `--lexicon`.

Пример записи:

```json
{
  "terms": {
    "заказ": ["ордер", "order", "покупка"],
    "поставщик": ["вендор", "мерчант", "продавец"]
  }
}
```

Линтер сообщит о синониме, который стоит вместо канонического термина.
