# Лексика УТР: замены и запреты

Списки поддерживают пункты 8.2.3.5 (метафоры, сленг, жаргон), 8.2.3.6 (иностранные
слова), 8.2.3.10 (глаголы вместо номинативных конструкций) и 8.2.3.11 (составные
сказуемые).

Пометка **[линтер]** означает, что `scripts/utr_lint.py` проверяет эту строку
автоматически. Остальные строки проверяет модель.

Глоссарий проекта имеет приоритет над этими списками (пункт 8.1.7). Передавайте
его через `--lexicon`.

## 2. Страдательный залог

Пункт 8.2.3.13 требует избегать страдательного залога в инструкциях.

| Запрещено | Замена |
|---|---|
| Данные сохраняются в кэш | Данные сохраняют в кэш |
| Запрос был обработан сервисом | Сервис обработал запрос |
| Соединение будет закрыто | Соединение закрывают |
| Файл может быть перезаписан | Файл перезаписывают. Или: перезапись файла возможна |
| Настройки задаются в config.yaml | Настройки задают в config.yaml |

**[линтер]** проверяет формы на «-ется», «-ются», «-ится», «-атся», «-ятся» и
краткие страдательные причастия.

Исключение: страдательный залог допустим, если исполнитель неизвестен и не важен,
а неопределённо-личная конструкция теряет смысл.

Правила не входят в ГОСТ Р 58049, но поддерживают пункт 8.2.3.2 (однозначность).

| Правило | Пример |

## 9. Порядок правки текста

1. Разбейте текст на предложения. Найдите предложения длиннее 20 слов (8.2.5.1).
2. Уберите причастные и деепричастные обороты (8.2.3.11).
3. Замените страдательный залог действительным (8.2.3.13).
4. Замените отглагольные существительные глаголами (8.2.3.10).
5. Разбейте цепочки из трёх и более существительных (8.2.3.10).
6. Проверьте порядок слов (8.2.3.4).
7. Замените лексику по спискам выше (8.2.3.5, 8.2.3.6).
8. Приведите термины к единой форме (8.2.3.7).
9. Вынесите перечисления в вертикальные списки (8.2.3.16).
10. Проверьте, что смысл, условия и числа сохранены (8.2.3.15, 8.2.4.1).

Шаг 10 обязателен. Правка, которая теряет условие, хуже исходного текста.
